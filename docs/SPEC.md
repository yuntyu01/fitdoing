# FitDoing - 프로젝트 지시서 (원본)

디자인 참고: [home.png](design/home.png), [onboarding.png](design/onboarding.png)

## 1. 앱 개요
- 이름: FitDoing (핏두잉)
- 한 줄: 식단·운동·수면 약속을 안 지키면 폰이 잠기는 앱. "안 찍으면 잠김."
- 대상: 헬스하는 20~30대, 하루 3~6끼 먹는 사람
- 핵심 원리: 잠금은 시간이 걸고, 행동이 푼다.
  - 끼니: 마감 시간 안에 앱 카메라로 사진(또는 바코드)을 찍지 않으면 잠금 → 찍으면 해제
  - 헬스: 정해진 요일·시간에 SNS 잠금 → 헬스장 도착(지오펜스)하면 해제, 실패 시 사진 인증
  - 취침: 취침 시각에 잠금 → 기상 시각에 해제
- 강도 3단계: 순한맛(알림+멈춤만) / 보통맛(2시간 잠금, 기본) / 매운맛(+단백질 최소 목표, 치팅 쿠폰, 랜덤 식후 사진)
- 탈출구: 전화·문자·지도 항상 허용 / 비상 해제 주 2회 / 휴식권(헬스) / 치팅 쿠폰(매운맛). 쿠폰 사용 시 5초 대기.
- 안전 규칙(절대): 칼로리 초과로는 절대 잠그지 않는다. 목표 칼로리는 기초대사량 아래로 설정 불가. 미성년자는 매운맛 불가. 표시 숫자는 반올림 + "약".
- 잠금 판단·해제는 전부 폰 안에서(오프라인) 동작해야 한다. 서버가 죽어도 잠금이 걸리고 풀려야 한다. 서버는 AI 중계와 기록 백업만.

## 2. 기술 스택
- 앱: React Native (Expo, dev client 사용) + 네이티브 모듈
  - Android(Kotlin): 잠금 엔진, 카메라, 지오펜스, 고정 알림
  - iOS(Swift): 스크린타임 API(FamilyControls/ManagedSettings/DeviceActivity) 확장, 라이브 액티비티 - 2차, 지금은 Android 우선
- 서버: Go + PostgreSQL. 사진 저장 Cloudflare R2. 결제 RevenueCat. 푸시 FCM.
- AI: Gemini 멀티모달. 키는 서버에만. 앱 → Go 서버 → Gemini. 응답은 JSON 스키마 고정 {items:[{name, amount}], kcal, carbs, protein, fat, confidence}. 사진은 긴 변 1024px로 줄여서 전송.
- 문자열은 처음부터 i18n (ko, en). 패키지명: com.fitdoing.app

## 3. 1차 범위 (이것만)
- 강도: 보통맛만 구현. 순한맛·매운맛은 설정 UI에만 자리 두고 비활성.
- 끼니 잠금 + 헬스 잠금(지오펜스) + 취침 잠금
- 사진 → AI 인식 → 보정(얼마나 먹었나 1/4·반·다, 나눠 먹음) → 기록
- 홈, 촬영, 기록 확인, 잠금 화면 3종, 헬스 상세, 기록(달력 + 날 카드), 설정, 쿠폰 시트, 온보딩 3단계
- 알림: 마감 30분 전, 잠금 시작, 헬스 시간 시작. Android 고정 알림에 남은 시간 카운트다운.
- 넣지 않는 것: 커뮤니티, 친구, 물, 식단 플랜, 음식 등급, 위젯, iOS

## 4. 화면 (구성 요약)
1. 온보딩: 목표(감량/유지/증량)+키·몸무게 → 끼니 수(3~6)와 끼니별 마감 시간 → 헬스 요일·시간·헬스장 위치, 취침/기상 시각 → 권한 안내(카메라, 위치, 사용 기록/오버레이) → 첫 끼니 촬영
2. 홈: 날짜 + 오른쪽 위 "휴식 1 · 치팅 2" → 요일 줄(오늘 박스, 기록한 날 점, 헬스 아령, 취침 달) → 끼니 타일 가로 줄(현재 마감 타일만 강조색, 나머지 흰색; 5개 넘으면 가로 스크롤, 현재가 가운데) → 헬스 긴 박스 → 취침 긴 박스 → 안내 한 줄("2끼를 14:00까지 못 찍으면 앱 2시간 잠금") → 오늘 합계(칼로리 막대 + 탄단지 숫자) → 식단 표(1끼~N끼, 빈 끼니는 끼니 목표를 연한 회색으로) → 오른쪽 아래 카메라 원 버튼(마감 10분 이하면 테두리 강조색) → 탭바(오늘·기록·설정)
3. 촬영: 앱 카메라만(갤러리 불가), 접시 원형 가이드, 셔터, 바코드 모드 전환
4. 기록 확인: 사진 → 인식 목록(수정 가능) → 얼마나 먹었나 → 나눠 먹음 체크 → 추정 칼로리·탄단지("약") → [기록하기]
5. 잠금(끼니): 검정 배경, "N끼 사진이 없어서 잠겼어요", 남은 시간 크게, [지금 찍어서 풀기], 전화·문자·지도 버튼, 작게 [비상 해제 · 주 2회 남음]
6. 잠금(헬스): "헬스장에 도착하면 풀려요 · 1.2km", [위치 안 잡힘 · 사진으로 인증], [휴식권 쓰고 풀기](5초 대기)
7. 잠금(취침): "잘 시간이에요 · 07:00에 풀려요", 전화·알람만
8. 헬스 상세: 거리, 남은 시간, 헬스장 이름·주소, 이번 주 3/5, [사진 인증], [오늘 쉬기]
9. 기록: 이번 달 요약 3개 → 월간 달력(다 찍음=강조색 채움, 일부=옅음, 잠김=점, 헬스=아령, 취침=달) → 누른 날 카드(칼로리·탄단지·끼니 사진 썸네일·헬스·잠금 여부)
10. 설정: 강도 / 끼니 수·마감 / 헬스 요일·시간·위치 / 취침·기상 / 쿠폰 장수 / 목표 칼로리·탄단지 / 항상 허용 앱 / 잠금 시간 / 비상 해제 횟수 / 사진 보관 정책
11. 쿠폰 시트: 휴식 1/2 · 치팅 2/2, 이번 주 사용 내역, 월요일 초기화

## 5. 디자인 규칙
- 토스 문법: 바탕 #F2F4F6, 카드 흰색 radius 16~20, 좌우 여백 20~24, 제목 22~26px 굵게, 설명 회색 15px, 하단 꽉 찬 56px 버튼, 목록은 카드 안 한 줄 + 화살표, 입력은 바텀시트, 말투는 "~해요"
- 색: 글자 #191F28, 보조 #6B7684, 강조색 하나 = 코랄 #F2542D (현재 타일, 칼로리 막대, 주요 버튼에만)
- 화면에서 가장 큰 숫자는 남은 시간 하나. 칼로리 숫자는 그보다 작게. 굵은 숫자는 화면당 2개 이하
- 잠금 화면만 검정 배경(#151515)
- 글꼴: Pretendard(한글), 숫자는 같은 서체 tabular
- 아이콘: 선 아이콘, 이모지 금지

## 6. 데이터 모델 (제안, 수정 가능)
- Settings{mode, meals:[{index, deadline}], gym:{days[], startTime, endTime, lat, lng, radius}, sleep:{bedTime, wakeTime}, coupons:{rest, cheat}, targets:{kcal, carbs, protein, fat}, allowedApps[], lockMinutes, emergencyPerWeek}
- MealLog{id, date, index, deadline, photoUri, barcode?, ai:{items[], kcal, carbs, protein, fat, confidence}, portion, sharedMeal, loggedAt, status: pending|logged|overdue|locked}
- GymLog{date, checkInAt, checkOutAt, verifiedBy: geofence|photo|rest}
- SleepLog{date, lockedAt, unlockedAt}
- LockEvent{type: meal|gym|sleep, startedAt, endedAt, releasedBy: action|time|emergency|coupon}
- CouponUse{type, usedAt, weekKey}
- 로컬 DB(SQLite/WatermelonDB 등) 우선, 서버 동기화는 나중

## 7. Android 잠금 엔진 요구사항 (네이티브 모듈)
- 포그라운드 서비스 + AlarmManager exact alarm으로 마감·취침·헬스 시각에 정확히 동작. 부팅 후 자동 복구(BootReceiver)
- 잠금 중 차단 대상 앱이 포그라운드로 올라오면 즉시 잠금 화면(전체 화면 Activity 또는 오버레이)을 덮는다. 감지는 UsageStatsManager 우선, 필요 시 AccessibilityService(용도 공개 문구 포함)
- 허용 목록: 전화, 문자, 지도, 알람, 본 앱. 나머지는 잠금 대상(설정에서 앱 선택 가능)
- 해제 트리거: 끼니 사진 저장 완료 / 지오펜스 진입(Play Services Geofencing) / 기상 시각 / 비상 해제 / 쿠폰
- 알림 우회 방지: 알림을 눌러 차단 앱이 열려도 잠금 화면이 먼저 뜬다
- 삼성·샤오미 배터리 최적화 예외 요청 화면 포함
- 모든 판단은 로컬. 네트워크 없이 동작
- RN에서 쓰는 API: startLock(type, until, allowedPackages), releaseLock(type), getLockState(), setSchedule(settings), 이벤트 콜백(onLockStarted, onLockReleased)

## 8. 진행 순서 (각 Phase 끝에 멈추고 보고)
- Phase 0: Expo RN 프로젝트 생성, 폴더 구조, 디자인 토큰, i18n, 로컬 DB, 탭 3개 빈 화면, Android 빌드(AAB) 가능 상태. → Play 비공개 테스트에 올릴 껍데기
- Phase 1: 온보딩 + 홈 + 설정 (잠금 없음, 순한맛 수준). 마감 카운트다운, 알림 3종
- Phase 2: 촬영 + 기록 확인 + Go 서버 Gemini 중계(JSON 스키마) + 기록 저장
- Phase 3: Android 잠금 엔진 네이티브 모듈 (별도 브랜치로 스파이크 먼저: 화면 없이 "마감 지나면 잠김, 사진 저장하면 풀림"만 실기기 검증)
- Phase 4: 헬스 지오펜스 + 취침 잠금 + 잠금 화면 3종 + 쿠폰·비상 해제
- Phase 5: 기록 탭(달력) + 마무리

## 9. 원칙
- 각 Phase 시작 전에 할 일 목록을 보여주고 승인받는다
- 새 라이브러리를 추가할 때는 이유를 한 줄로 적는다
- 잠금 엔진은 RN과 독립된 모듈로 만든다(나중에 다른 앱에서 재사용)
- 사진과 위치는 폰 밖으로 나가는 경우를 코드 주석과 개인정보 문구에 명시한다
- 테스트 가능한 로직(마감 계산, 쿠폰 주간 초기화, 순공/합계 계산)은 단위 테스트를 쓴다

## 10. 결정 사항 (2026-09-27)
- 디자인·기능은 시안 이미지(docs/design/)를 우선한다. 지시서와 다르면 이미지를 따른다.
  - 강조색은 검정(#191F28 계열). 코랄 미사용.
  - 홈: 오른쪽 위 "N일째 기록 중", 헬스는 끼니 줄 안의 타일("헬스 · 3/5, 19:00까지"), 취침 긴 박스 없음.
  - 헬스 설정은 "도착 시간" 하나 + 헬스장 이름·주소.
- 온보딩에 나이·성별 입력은 넣지 않는다.
- 사진: 기본은 Gemini 분석용으로만 서버를 거쳐 전송(서버에 저장 안 함)하고 폰에만 보관. R2 백업은 사용자가 켤 때만.
- 저장소: git + GitHub. Go 서버는 KoDeploy에 배포.
